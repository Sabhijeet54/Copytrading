# Change log — 2026-10-13: broker takeover, live feed, fast copy path, risk

## ⚠️ Breaking changes / migration

1. **DB migration** `packages/database/prisma/migrations/20261013000000_broker_takeover`
   - `BrokerAccount`: the full unique `(broker, brokerClientId)` is **dropped** and replaced by a
     **partial unique index** `BrokerAccount_connected_client_key … WHERE status = 'CONNECTED'`.
   - New columns: `BrokerAccount.mode` (`TRADING` | `DATA_ONLY`), `disconnectReason`, `disconnectedAt`;
     `StrategyFollower.fixedLots / maxLots / maxTradesPerDay / allowedSegments`; `CopyOrder.latencyMs`;
     `User.telegramChatId`. New enum `BrokerAccountMode`, new `AuditAction` values.
   - Existing **MASTER** broker accounts are converted to `DATA_ONLY`.
   - Apply with `npm run prisma:deploy` (or `prisma:migrate` in dev).
   - Prisma cannot express partial indexes in `schema.prisma`. If a future `prisma migrate dev` generates
     `DROP INDEX "BrokerAccount_connected_client_key"`, **delete that line** from the generated migration.
2. **Master accounts never place orders.** A master order from the Master desk is now a *signal*
   (`brokerOrderId = SIG-…`) mirrored to clients only. Trades the master takes in the Kite/Angel app are
   still detected by the poller and mirrored.
3. **New dependencies** — run `npm install`:
   API `@nestjs/websockets`, `@nestjs/platform-socket.io`, `socket.io`; web `socket.io-client`.
4. **New env vars** (all optional, see `.env.example`): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`,
   `AUTO_SQUARE_OFF_TIME` (default `15:15`, empty disables), `FEED_STALE_SECONDS`, `ORDER_RATE_PER_SEC_ZERODHA`,
   `ORDER_RATE_PER_SEC_ANGEL`, `TOKEN_EXPIRY_CHECK_MS`, `RISK_POLL_INTERVAL_MS`.
   Web (optional): `NEXT_PUBLIC_SOCKET_URL` to connect Socket.IO straight to the API instead of via `/api/socket.io`.

## Broker takeover (bug fix)
`BrokerSessionService.saveSession` no longer throws "already linked to another user". In one transaction it
disconnects any other user's CONNECTED row for the same client ID (credentials deleted, `DISCONNECTED`,
reason *"Account doosre user ne connect kar liya"*, their copy subscriptions OFF, audit `BROKER_TAKEN_OVER`)
and connects the new user. After commit the old user gets socket `broker.taken_over` + a notification.
A concurrent duplicate is rejected by the partial index and retried once.

## Order fast path
`ClientRegistryService` keeps every copying follower in memory (pre-built adapter with decrypted token,
settings, day counters, net copy positions). `CopyEngineService.onMasterTrade` → one Redis round trip
(idempotency + kill switch) → `Promise.all` over followers → per-broker token-bucket throttle → keep-alive
undici agent → 1 retry only for 429/502/503/connection-refused → MasterTrade/CopyOrders/audit/notifications
persisted **after** orders are out. Latency (`latencyMs`) per order; dashboard shows the average.
