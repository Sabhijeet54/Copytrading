# Changes — 27 Oct 2026 (software trade ledger vs broker execution)

**Database migration required:** `20261027000000_software_trading_mode` (adds `User.tradingMode`, back-fills
`LIVE` for clients whose real trading account was already on Live). Run `npm run prisma:deploy` (and
`npm run prisma:generate`), then restart the API, worker and web.

## Concepts

| | What it is | Where it is shown |
|---|---|---|
| **Software trading mode** | `User.tradingMode` = `PAPER` / `LIVE`, set by the Dashboard switch. Independent of any broker. | Dashboard |
| **Strategy trade (software ledger)** | One per *strategy entry signal × client*, recorded for every valid strategy trade whatever the broker does. **Strategy Trade ID** = id of its entry order row (`T-XXXXXXXX` short form). Status Open / Closed comes from the strategy signal (and software exits like exit-all / square-off), never from the broker. | Portfolio → Positions, Dashboard |
| **Broker execution** | The order the software created for that trade and what the broker did with it: Paper (not sent), Not sent (no broker), Pending, Submitted, Open, Executed / Filled, Partially filled, Rejected (+reason), Cancelled, Failed, Skipped. Updated only from broker responses / order reconciliation. | Portfolio → Orders (linked by Trade ID) |
| **Software P&L** | Strategy trades at strategy prices (realized + unrealized). Includes broker-rejected / not-sent Live trades. | Dashboard, Positions |
| **Broker-executed P&L** | Actual Demat fills only (real filled quantity × real fill prices). Never includes paper or not-executed trades. | Dashboard, Positions (separate figure) |

## 1. Dashboard Live / Paper switch
- `POST /follow/trading-mode` now changes only the software mode. It needs **no broker**, never connects,
  disconnects, authenticates or generates a token, and places no broker order. Re-sending the current mode is a no-op.
- PAPER → LIVE still closes open *paper* trades in the software (simulated, at LTP) so a later strategy exit is
  never sent to a broker for a position that only existed on paper.
- Real broker accounts follow the switch (`isPaper`) so every exit path treats them consistently; broker status /
  tokens are untouched. Demo licence stays Paper.
- The Dashboard broker card is display-only ("Manage it in Broker connection").

## 2. Paper trading without a broker
- Every client gets an internal **paper ledger** account (broker `MOCK`, created on demand). It is not a broker
  connection and is hidden from the Broker connection page.
- Following / activating a strategy no longer requires a broker (`brokerAccountId` is optional in
  `POST /follow/strategies/:id`; `.../subscriptions/:id/start` no longer checks the broker). Master / admin
  "assign + start" also works without a broker.

## 3 & 4. Live mode
- Live + valid broker connection → order sent to the broker as before.
- Live + no / expired / invalid broker connection → the strategy trade is recorded and shown in Positions; the
  order row is `FAILED` with `errorCode = NOT_SENT` ("Not sent · no broker"). Nothing is ever sent for it later.
- Broker rejection / failure never removes the strategy trade; it is shown only in Orders.
- Positions shows Live trades as Live (with a neutral hint: "Executed at broker" only when a fill is confirmed).
- Connecting a broker in Broker connection re-points subscriptions that had no broker (or only the paper ledger) to
  that account; copy status is not changed.

## 5. Dashboard / Portfolio use the ledger
- `GET /follow/dashboard`: `tradingMode`, `todayPnl` (software), `software {trades, open, closed, realizedPnl,
  unrealizedPnl, totalPnl}`, `brokerPnl`, per strategy `todayPnl` (software) + `brokerPnl`.
- `GET /follow/trades`: ledger rows `{tradeId, tradeRef, mode, status, entry/exit, realizedPnl, unrealizedPnl,
  pnl, execution}` + `software` summary + `brokerExecuted`.
- Master client list / client detail: `todayPnl` = software, new `brokerPnl` and `tradingMode`.

## 6. Broker connection only in the Broker connection section
- Broker OAuth callbacks now land on `/broker` (was `/dashboard`); the dashboard no longer handles broker callbacks.

## 7. Orders section
- New `GET /follow/orders` (and the same rows in `/follow/portfolio.copyOrders`): Strategy Trade ID, instrument,
  side/qty, order type, price, broker + broker order ID, `brokerStatus`, filled qty, execution price,
  rejection reason / error. Exit orders link to the trade they close.

## Duplicate / safety guarantees (unchanged mechanisms, now covering all rows)
- One master signal → at most one order row per client (`masterTradeId + followerUserId` unique, Redis SET NX).
- Mode switching places no broker order; paper exits are booked where the paper position is held and never
  create an opposite paper position for a trade that was opened Live.

## Tests
- New `apps/api/test/e2e/software-ledger.e2e-spec.ts` (fake broker adapters, real Postgres + Redis): paper
  without broker, live without broker, executed, rejected, partial fill, failed placement, master exit / closed
  trades, Dashboard software vs broker P&L, Trade ID linking, duplicate signal, mode switching.

## Known limits
- Live trades recorded while no broker was connected are not sent retroactively when a broker is connected.
- Switching LIVE → PAPER does not close positions already held at the broker; manage those at the broker.
